Getting Started

YP Scraper Pro extracts business listings from Yellow Pages at scale. You can use it through the Web UI, the CLI, or the REST API.

Quick Start (Web UI)

  1. Log in with your credentials
  2. Enter keywords (business categories) and locations
  3. Set concurrency and enable proxies
  4. Click Start Scraping and watch real-time progress
  5. Download your CSV when complete

Quick Start (CLI)

# Login (saves session for future commands)
python3 yp-cli.py login --user mike --password yourpassword

# Scrape and wait for results
python3 yp-cli.py scrape \
  --keywords "plumbers,electricians,roofers" \
  --locations "Miami FL,Houston TX" \
  --pages 2 --concurrent 100 --proxies \
  --wait --output leads.csv

Web UI Guide

Keywords

Comma-separated Yellow Pages business categories. Examples: plumbers, roofing contractors, HVAC services

Locations

Comma-separated in "City ST" format. Examples: Miami FL, Chicago IL, United States

Concurrency

Number of parallel scraping contexts. Each uses ~10MB RAM. Match this to your proxy count for best results. Without proxies, keep it low (1-5) to avoid rate limiting.

Pages per Search

Yellow Pages shows ~30 results per page. 5 pages = ~150 businesses per keyword+location combo.

Business Limit

Set to 0 for unlimited. Otherwise, the scraper stops after reaching this many total businesses.

CLI Tool

The CLI (yp-cli.py) lets you run scrapes from the terminal or from AI agents like Claude Code.

Installation

pip install requests
# Download yp-cli.py from your scraper instance or GitHub

Commands

login - Authenticate and save session

scrape - Submit a scrape job (with optional --wait)

status - Check job progress

results - List available result files

download - Download CSV results

suggest - Get AI-powered keyword/location suggestions

Machine-Readable Output

Add --json to any command for JSON output, perfect for piping into other tools.

python3 yp-cli.py --json status
python3 yp-cli.py --json scrape --keywords "plumbers" --locations "Miami FL" --wait

API Reference

All endpoints require authentication (session cookie from POST /login).

POST /api/start-scrape

{
  "keywords": "plumbers, electricians",
  "locations": "Miami FL, Houston TX",
  "max_pages": 2,
  "concurrent": 100,
  "use_proxies": true,
  "max_businesses": 0,
  "chunk_output": false
}

Returns: {"success": true, "job_id": "abc123", "total_searches": 4}

GET /api/progress?job_id=abc123

Returns job status, progress (completed/total/businesses/errors), and output files.

POST /api/stop-scrape

Body: {"job_id": "abc123"} — stops a running job, saves partial results.

GET /api/list-results

Returns all CSV files with size, row count, and creation date.

GET /api/download?file=scrape_results_abc123_20260603.csv

Downloads a specific CSV file.

POST /api/ai-suggestions

{"icp": "roofing companies in the southeastern US"}

Returns suggested keywords and locations from Grok AI.

Proxies

Proxies are essential for large scrapes. Without them, Yellow Pages blocks your IP after ~10 requests.

How It Works

  • Each concurrent browser context gets assigned a different proxy
  • 249 proxies = 249 different IP addresses = no rate limiting
  • Proxies with repeated failures are automatically skipped

Upload Format

Upload a text file with one proxy per line:

host:port:username:password
192.168.1.1:8080:user:pass

Recommended Providers

  • Webshare — cheap rotating proxies, good for scraping
  • SmartProxy — residential proxies, higher quality
  • BrightData — enterprise, most reliable

AI Suggestions

Powered by Grok (xAI). Describe your ideal customer profile and get keyword + location suggestions automatically.

Example

Input: "Small commercial roofing contractors in the southeastern United States"

Output: 10-50 relevant Yellow Pages keywords + 10-50 target cities.

The API key is configured globally — all users can use AI suggestions without their own key.

Architecture

The app runs as three containers:

  • Web — Flask frontend, stateless, serves UI and API (~80MB RAM)
  • Worker — Picks up jobs from Redis, runs Chromium scraper (~120MB idle, ~3GB peak)
  • Redis — Job queue, state, user auth, log streaming (~4MB RAM)

How Scraping Works

The worker uses a shared browser architecture: one Chromium process with many lightweight browser contexts (like incognito windows). Each context costs ~10MB vs ~300MB for a separate browser. This is why we can run 249 concurrent scrapes in 3GB of RAM instead of 75GB.
